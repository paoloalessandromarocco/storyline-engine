ComfyUI Storie Visive — Gli Script Python

ComfyUI Tutorial Didattica Python Storyboard

Questo post copre il percorso complementare a quello del grafo a nodi — vedi Il Grafo dei Nodi — script Python e bash che automatizzano la generazione (essenzialmente patcher.py e sweep.py)1, utili ad esempio per trattare aspetti come i cicli, le multi-varianti e la ripetizione di aggregati di nodi — difficili da gestire soltanto tramite grafi. In questo post vedremo l'utilizzo di queste funzioni applicate a 14 inquadrature della storia Sotto l'Asfalto, con i due personaggi ricorrenti: John e Elena.

Il Grafo dei Nodi — una pipeline vista nella pagina relativa — è composto da 50+ nodi ComfyUI. Scalare questo tipo di grafo per generare 14 inquadrature significa replicare identici sottografi quattordici volte — ossia moltiplicare una decina di nodi per 14 in un unico grafo. Questo comporta: gestire prompt, pesi e riferimenti alle immagini, inquadratura per inquadratura, nel JSON. Un processo che diventa rapidamente impraticabile2. È il problema risolto dagli script qui descritti.

  1. 01

    Vibe-code: diventare sviluppatore senza scrivere codice

    Il vibe-code è la pratica di usare un assistente AI — Claude, GPT, Gemini e altri — per generare codice funzionante descrivendo il problema in linguaggio naturale. Non si scrive direttamente codice Python, ma si descrive il problema all'LLM: il modello scrive il codice, che si può eseguire direttamente oppure far eseguire al modello stesso, che simula l'interprete Python. Il risultato si comporta esattamente come se un developer lo avesse costruito per voi. Se occorrono dei cambiamenti, si organizza un file di configurazione, dove si descrivono le proprietà delle funzioni del vibe-code: in teoria basta cambiare i valori di questi parametri per ottenere esecuzioni diverse del codice. È la grande rivoluzione dell'AI nella programmazione: democratizzare il gergo degli sviluppatori riducendolo a linguaggio naturale, cambiando l'organizzazione dei team.

    In questa pipeline la divisione dei ruoli è chiara. L'AI gestisce il livello tecnico — generare il JSON del grafo di nodi, scrivere gli script di patching e di sweep.3 L'operatore umano gestisce il livello creativo — descrivere come appare ogni inquadratura (le luci, le focali, il posizionamento della mdp ecc.), impostare i pesi che bilanciano l'identità facciale, scegliere quali frame generati conservare, ecc.

    Ritornando a questo progetto, il flusso di lavoro usa cinque file: a) un JSON del grafo di base (generato una volta da Claude a partire da una descrizione in linguaggio naturale della pipeline), b) un file di configurazione che si può agevolmente modificare prima di ogni ciclo di generazione, c) due script di automazione (anch'essi generati da Claude e riutilizzabili in altri progetti), d) le immagini di riferimento dei personaggi. Nessuna sintassi da imparare. Un solo comando da lanciare. Compilare il file di config ed eseguire uno script è l'intera complessità dell'interazione tecnica.

  2. 02

    Il progetto

    L'esempio usato in questo post è uno storyboard di 14 inquadrature chiamato bar_14shots, ambientato in un wine bar con due personaggi ricorrenti — Jim e Barbara. Le loro immagini di riferimento (corpo intero/turnaround, ritaglio del volto, riferimento a due personaggi) sono gli stessi file descritti nella pagina di configurazione. Ogni inquadratura ha uno stile iperrealistico. I moduli coinvolti sono: Flux.1-dev come modello diffusivo base, PuLID per il blocco dell'identità facciale, XLabs IPAdapter per la coerenza di corpo e abbigliamento, ControlNet depth per la struttura spaziale.

    Prima di scrivere qualsiasi configurazione o eseguire qualsiasi script, è utile descrivere il progetto in linguaggio naturale. Un brief di progetto chiaro include: il numero di inquadrature; i due personaggi; quali inquadrature presentano un solo personaggio e quali entrambi (le inquadrature a due personaggi richiedono una catena PuLID + IPAdapter doppia nel grafo); l'ambientazione dell'interno del bar, ancorata da un'immagine di riferimento wall1.png; e il registro visivo generale — in questo caso iperrealistico e cinematografico.

    Ogni inquadratura può variare indipendentemente dal framing (piano medio, campo lungo, primo piano), dalla focale, dall'angolo di ripresa e dagli oggetti di scena. Tutta quella variazione è controllata attraverso il file di configurazione — non per mezzo dell'interfaccia di ComfyUI e modificando il grafo. In questo progetto, una volta che il grafo è generato da Claude, diventa una infrastruttura fissa e non viene mai più toccato.

Vuoi i passaggi concreti, operativi — i cinque file, la sequenza di esecuzione e il passaggio di post-processing? Vedi Istruzioni per scrivere e lanciare il workflow di questa sezione.

  1. Il nome richiama il monkey patching: la modifica o estensione a runtime di classi, funzioni o oggetti senza toccare il codice sorgente originale. Qui si applica al grafo ComfyUI: patcher.py prende il grafo di base (mai modificato) e vi inietta a runtime i valori del file di configurazione — prompt, pesi, riferimenti immagine — producendo i file PATCHED pronti per la generazione. sweep.py automatizza la generazione stessa: fa variare un singolo parametro su una lista di valori e lancia una chiamata API per ciascuno, per confrontare rapidamente più risultati. ↩
  2. Pur essendo teoricamente possibile, con il vibe-code, moltiplicare i sottografi e collegarli all'infinito, in pratica si incontrano problemi di leggibilità visiva del grafo e di esecuzione effettiva con troppi nodi. Conviene quindi pianificare il progetto dividendolo in più grafi distinti, gestendo opportunamente gli output di uno come input del successivo. ↩
  3. Internamente sono semplici: patcher.py carica il JSON del grafo come un dizionario Python, cerca i nodi target tramite il loro ID (sempre lo stesso, perché il grafo è fisso) e sovrascrive i campi dei loro parametri con i valori letti da shots_config.py — poi salva il risultato in un nuovo file. sweep.py fa lo stesso lavoro di patcher.py in un ciclo: per ogni valore nella lista, inietta quel valore nel nodo, invia il JSON patchato all'endpoint API di ComfyUI e salva l'immagine restituita con un nome che include il valore usato. ↩
