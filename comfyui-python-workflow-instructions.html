ComfyUI Python Workflow Script

Questi sono i passaggi concreti e operativi per scrivere e lanciare il workflow Python/bash introdotto in ComfyUI Storie Visive — Gli Script Python: i cinque file del workspace, la sequenza di esecuzione e il passaggio di post-processing.

  1. 01

    I passaggi

    Il workspace contiene cinque file in due livelli. Il livello statico (creato una volta, mai modificato di nuovo): il JSON del grafo base e i due script di automazione. Il livello attivo (modificato prima di ogni ciclo di generazione): il file di configurazione e le immagini di riferimento dei personaggi in ComfyUI/input/.

    File Generato da Ruolo
    bar_14shots.json Claude — una volta Grafo base: tutti i collegamenti. Mai modificato.
    shots_config.py Tu — ogni ciclo Contenuto: prompt, pesi, riferimenti, seed per inquadratura.
    patcher.py Claude — una volta, riutilizzato Legge JSON base + config, inietta il contenuto, scrive i file PATCHED.
    sweep.py Claude — una volta, riutilizzato Invia N chiamate API variando un parametro, salva N immagini.
    jim_face.png, barbara_face.png … Tu — caricati una volta Riferimenti di personaggi e ambienti in ComfyUI/input/.

    1. Generare il grafo di base. Descrivi la pipeline bar_14shots a Claude: 14 inquadrature, Jim e Barbara, interno di wine bar, una catena PuLID + IPAdapter + ControlNet per ogni inquadratura a singolo personaggio, una catena doppia per le inquadrature con entrambi i personaggi. Claude restituisce il bar_14shots.json completo. Copialo nel workspace. È il solo momento in cui si interagisce con la struttura del grafo — da qui in poi resta congelata.

    2. Configurare shots_config.py. Apri il file e compila i campi per l'inquadratura su cui stai lavorando. Otto campi definiscono ogni inquadratura: wall (l'immagine di riferimento depth che imposta anche l'ambiente), framing, focal e angle (il linguaggio cinematografico, aggiunto al testo del prompt), objects (oggetti di scena), clip_l e t5xxl (la descrizione principale della scena per i due encoder di testo di Flux) e neg (prompt negativo). Un nono campo, prev_image, è riservato alla continuità visiva tra le inquadrature e non ancora collegato nella versione attuale.1

      # shots_config.py (excerpt) BASE_GRAPH = "bar_14shots" # patcher.py and sweep.py derive all file paths from this constant SHOTS = { "1A_Barbara_Enters": { "wall": "wall1", # depth / environment reference "framing": "medium shot", "focal": "50mm", "angle": "eye level", "objects": "wine glass, dim ambient light", "prev_image": None, # reserved — not yet wired "clip_l": "Barbara walks into the wine bar, elegant, cinematic...", "t5xxl": "Barbara walks into the wine bar, elegant, cinematic...", "neg": "blurry, deformed, low quality", "pulid_weight": 0.50, "ipadapter_weight": 0.60, "seed": 42, }, "1B_Jim_Reacts": { ... }, }

    3. Eseguire patcher.py. Lo script legge bar_14shots.json e la config attiva, inietta tutto il contenuto nei campi corretti dei nodi e scrive due file: bar_14shots_PATCHED.json (formato GUI — caricabile nel browser ComfyUI per ispezionare i nodi prima di generare) e bar_14shots_PATCHED_API.json (formato API — usato da sweep.py e dalle chiamate API dirette). Caricare il file GUI nel browser prima di generare è opzionale, ma utile quando si fa il debug di un'inquadratura per la prima volta.

      python3 /workspace/patcher.py --shot 1A_Barbara_Enters # optional check before generating: # ComfyUI browser → Load → bar_14shots_PATCHED.json → inspect nodes → Queue

    4. Eseguire sweep.py per l'esplorazione dei parametri. Invece di generare un'immagine e indovinare quale peso è migliore, sweep.py cicla su una lista di valori per un singolo parametro, invia una chiamata API per ogni valore e salva l'immagine di output corrispondente. Usalo per calibrare PuLID (intensità dell'identità facciale), IPAdapter (intensità del riferimento per corpo e abbigliamento) o per testare seed diversi prima di impegnarsi in una generazione finale.

      # calibrate face identity: 4 values → 4 output images compared side by side python3 /workspace/sweep.py --shot 1A_Barbara_Enters \ --param pulid_weight --values 0.2,0.35,0.5,0.65 # calibrate body/clothing reference strength python3 /workspace/sweep.py --shot 1A_Barbara_Enters \ --param ipadapter_weight --values 0.3,0.5,0.7,0.9 # test random seeds before the final run python3 /workspace/sweep.py --shot 1A_Barbara_Enters \ --param seed --values 42,99,123,777

      Parametri esplorabili: pulid_weight, ipadapter_weight, denoise, seed, cfg, steps. Lo script ricava il percorso del JSON API dalla costante BASE_GRAPH definita in shots_config.py — nessun argomento aggiuntivo necessario.

  2. 02

    Post-processing

    Una volta generata un'inquadratura, piccoli difetti possono essere corretti senza rieseguire l'intera pipeline. Un set separato e leggero di tre file applica il raffinamento img2img: prende il frame già generato come ancora strutturale e riesegue la diffusione su di esso a un livello di rumore controllato, guidato da un prompt correttivo. Il risultato si colloca tra l'originale e una rigenerazione completa — più vicino all'uno o all'altro a seconda di quanto rumore si inietta.

    Il parametro di controllo è denoise. La tabella mappa il suo intervallo al tipo di cambiamento che produce:

    denoise Effetto Uso tipico
    0.15 – 0.30 Micro-correzione — quasi invisibile Artefatti di pelle, bordi sfocati, nitidezza occhi
    0.30 – 0.50 Moderata — struttura intatta Elemento di sfondo errato, luce irregolare
    0.50 – 0.70 Forte — cambiamento significativo Deriva del volto, correzione di mood o stile
    0.70 – 0.90 Quasi-rigenerazione — solo composizione Revisione completa di palette o atmosfera

    Il set di tre file segue lo stesso schema della pipeline principale: un file di config per la direzione creativa, script e JSON del grafo per l'esecuzione tecnica. postprocess_config.py è l'unico file che si modifica: si dichiara l'immagine di input, il prompt correttivo e il valore di denoise. postprocess_run.py è il motore (generato da Claude). postprocess_graph.json è un grafo API a 11 nodi, statico e mai modificato.

    python3 /workspace/postprocess_run.py # postprocess_config.py: # INPUT_IMAGE = "outputs/1A_Barbara_Enters_00042.png" # PROMPT = "Barbara, sharp face, correct the left hand" # DENOISE = 0.35 # moderate — keeps face and composition stable

Sequenza completa — tutti i passaggi

  • Il Grafo dei Nodi: un percorso completo nel grafo di nodi di ComfyUI, nodo per nodo — DualCLIPLoader, VAELoader, IP-Adapter, ControlNet depth, KSampler. Vedi il post gemello ComfyUI Storie Visive — Il Grafo dei Nodi.
  • Setup: installare i pack di nodi personalizzati, scaricare i pesi dei modelli, caricare i riferimenti dei personaggi in ComfyUI/input/. Vedi la pagina di configurazione.
  1. Descrivere la pipeline a Claude → ricevere bar_14shots.json → copiare nel workspace.
  2. Modificare shots_config.py: impostare prompt, wall, framing, pesi, seed per l'inquadratura target.
  3. Eseguire patcher.py → bar_14shots_PATCHED.json + _PATCHED_API.json. Opzionale: caricare _PATCHED.json nel browser ComfyUI per verificare i valori dei nodi.
  4. Eseguire sweep.py --shot NOME_SHOT --param pulid_weight --values 0.2,0.35,0.5,0.65 → 4 varianti generate e salvate automaticamente.
  5. Impostare immagine + prompt correttivo + denoise in postprocess_config.py, poi eseguire postprocess_run.py. Ripetere con denoise più alto se il primo passaggio non è sufficiente.

I passaggi b–d formano un ciclo iterativo. Per uno storyboard di 14 inquadrature, aspettarsi diversi cicli: iniziare con gli sweep per calibrare i pesi, generare tutte le inquadrature, poi post-processare i frame che richiedono correzioni.

  1. Il campo prev_image è destinato a reintrodurre l'output di un'inquadratura precedente nell'IPAdapter di quella successiva — una tecnica per la continuità visiva tra frame consecutivi (coerenza dell'abbigliamento, corrispondenza della luce, continuità della camera). Richiede l'aggiunta di un nodo IPA dedicato per ogni inquadratura nel grafo. È documentato in shots_config.py affinché una revisione futura possa collegarlo senza modificare il formato della config. ↩
